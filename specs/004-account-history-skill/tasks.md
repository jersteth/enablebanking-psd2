## Design Deviations
1. **Session resolution reuses `ensure_session`.** `history` calls `ensure_session(..., interactive=False)` instead of its own read-only resolver, so the stored-metadata PSU rule and the `/aspsps` fallback for 002-migrated records are shared. A local validity check runs first, so accounts without a usable record cost no API call. The `/aspsps` fallback isn't memoized per bank per run; only migrated v1 records reach it.
2. **`history` bypasses the `CommandResult` layer.** `commands.history(args) -> int` is called from `cli.main`, because `fetch_history` owns the config and client lifecycle. Its output is always JSON, so there is no render or envelope; `--json` is accepted as a no-op.
3. **`fetch_history` extras.** It gained `progress: TextIO` (for the CLI's `--verbose`). Its `client` argument takes an instance or a factory, and an injected instance is never closed.
4. **New `bootstrap.py`.** `load_signer`/`make_client` moved from `cli.py` into it, shared by the CLI and the Python API.
5. **`authorize` default target.** Without `--account`/`--all` it targets every account, the same as `--all`.
6. **`authorize` with an account missing from the consent** doesn't abort. The consent is stored, and that account's row reports `missing` with guidance.
7. **`--no-cache` means `use_cache=False` only.** The design also set `max_age=0`; the effect is the same.
8. **Warnings are `{part, message, http_status}`** for every warning: failed parts, truncated paging (`part: "transactions"`) and the stale fallback (`part: "account"`).
9. **`history` takes no app overrides.** There is no `--app-id`/`--key`/`--psu-ip`, so it runs from config only, which keeps the CLI and the API identical.
10. **A 429 on balances or details keeps the transactions.** The part becomes `null` with a warning, matching R3 AC4; the design failed the whole account. A 429 on the session check or transactions still falls back to a stale cache entry, or `rate_limited`.
11. **No 429 retries for `history`.** Its client is built with `retry_rate_limits=False`, because a daily cap won't clear within a run.
12. **Cache changes:**
    - The key includes the session ID, so a new consent never serves the old consent's data.
    - The local consent check runs before the cache, so a revoked or expired consent is reported as `consent_required` and not served from the cache.
    - Results with warnings aren't cached, so a partial result isn't frozen for `max_age` minutes.
13. **One session check per bank per run.** One `Context` per `history` run, and `flow.live_session` memoizes `GET /sessions/{id}` per session (also in `authorize --status`). Accounts sharing a bank consent check it once. `authorize --status` applies the 7-day margin to the live `valid_until` from Enable Banking as well as the stored one.
14. **Flow structure:**
    - `Context.hooks` is optional; `None` means non-interactive. `flow.consent_bank` gives bank-level consent without account matching, and `authorize` uses it.
    - `flow.fetch_transactions` is the one transaction fetch (API order, plus the 90-day hint), used by `run` and `history`.
15. **Shared helpers:**
    - Atomic 0600 writes live in `fileio.write_text_atomic`, used by the session store, the cache and exports.
    - `Balance.type_label` and `AccountDetails.flattened()` moved to `eb/models.py`, so `contract.py` no longer imports `output.py`.
    - Include parsing is `config.parse_include`, and totals use `transactions.summarize_amounts`.
